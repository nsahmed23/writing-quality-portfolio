# Enforceable type contracts

| Type | Reader | Must | Must not | Acceptance check |
|---|---|---|---|---|
| Tutorial | Learner acquiring skill under guidance | Complete tested path; meaningful steps; early/visible results; expected outputs; notice cues | Offer many choices; inventory options; lecture at length; assume learner judgment | A learner can repeat the path and reach the promised result safely |
| How-to | Competent user accomplishing a real goal | State goal/prereqs; executable and adaptable directions; necessary branches/warnings | Teach from first principles; exhaustively describe product; digress into theory | A qualified user can solve the named problem in context |
| Reference | User looking up authoritative facts | Define scope; precision, neutrality, completeness, standard pattern; constraints/errors/types | Create a learning journey; argue; hide facts inside prose | Target facts are findable, consistent, and accurate for the version |
| Explanation | Reader building understanding | Bounded topic; causes, context, tradeoffs, connections, alternatives | Masquerade as procedure or fact catalogue | Reader can explain why/how concepts relate and where the account stops |

**Mixing rule:** This portfolio inference permits clearly bounded typed sections in one container. Flag unmarked switches that break the dominant contract; do not cite it as Procida’s express “mixed document” policy.
