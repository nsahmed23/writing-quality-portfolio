# Automated writing comparison (development protocol)

This package implements `automated_proxy`, a separate workflow from the archived editing-pilot human-review protocol. No human grade is required: missing evidence, failed judge calibration, unstable judgments, and close comparisons end in an automatic **inconclusive** result. Software demos verify plumbing only; they cannot approve a candidate. The public controls and references are development material, not a blind holdout or a measure of expert writing quality.

The approach adapts [Meta's Unslopping AI](https://facebookresearch.github.io/RAM/blogs/unslop/) lesson about compact, task-aware rubrics and evaluator calibration. It does not reproduce RL-XAR or train model weights. The six rubric criteria cover purpose, meaning, useful detail, economy, cohesion and voice; no word blacklist defines quality.

Run from the repository root with Python 3.11 or later. The demo needs no API key and makes no model call:

```sh
python -m evaluation.benchmark_v2.automated validate --suite evaluation/benchmark_v2/automated/data/controls.json --rubric evaluation/benchmark_v2/automated/data/rubric.json
python -m evaluation.benchmark_v2.automated validate --suite evaluation/benchmark_v2/automated/data/references.json --rubric evaluation/benchmark_v2/automated/data/rubric.json
python -m evaluation.benchmark_v2.automated demo --out .eval-runs/demo-1
python -m unittest discover -s tests -p 'test_automated_*.py'
```

Use a **new** output directory for each invocation; runs refuse to overwrite old evidence. The demo creates `.eval-runs/` on first use. Its `complete: false` and `eligible: false` are expected: it saves `synthetic-response-valid.bin` and `synthetic-response-invalid.bin` to demonstrate a functioning synthetic path and a rejected judgment. This is a successful software demo, not a broken installation or a live quality verdict.

Suite validation rejects identical normalized prompt, context and candidate pairs assigned to different document IDs, even within one split; repetitions under the same document ID remain valid. This prevents copied cases from inflating independent calibration or comparison document counts. An optional case field `cluster_id` groups documents that share a source; a document belongs to one cluster and a cluster never spans splits. `compare --split SPLIT` (default `test`) picks the split to score. `--calibration-suite PATH` names the suite that issued the certificate when it differs from the suite being scored, so that overlap with the labeled controls can be counted; a `test` comparison that overlaps them is refused. `CONTRACT.md` in this folder states these rules and the report fields they write.

## Live adapter configuration

Copy `adapters/example-config.json` to `adapters/local-config.json` in the same directory (Git ignores that path, so local executable paths stay out of commits) and edit the command arrays for your installed, trusted local adapters. The example contains **one** Codex judge family, which is insufficient for an eligible live comparison: add a genuinely distinct second judge family. Each judge has a distinct `id` and a `family`; a complete live comparison needs at least two independent judge families. The config declares `schema_version: 1`, `judges: [{id, family, command: [executable, argv...] }]`, optional `writer` and `optimizer` with the same shape, `timeout_seconds` (default 300, up to 600), and `max_calls` (default 2000). A configured command receives one JSON request on stdin and normally writes one raw UTF-8 JSON response to stdout. Commands execute as argv with `shell=False`; treat them as trusted software, not an OS sandbox. Config-relative executable/script paths resolve from the config directory. The included Codex CLI adapter is one available command; for another model CLI that accepts a prompt on stdin and emits raw JSON on stdout, the generic bridge accepts `python generic_json_adapter.py -- MODEL_CLI ARG...` in the command array, and agy goes through `stdin_repo_adapter.py` (prompt on stdin) or `prompt_arg_adapter.py` (prompt as the value of `-p`), both described below. Each adapter script has its own prompt transport, listed in the next paragraph. Supply credentials through the normal environment, not in config files. The runner preserves request, first response, stderr, exit status, elapsed time and hashes. Judge requests exclude candidate identity, private expected labels and suite files, but provider retention policies still apply.

The scripts in `adapters/` and how each one hands the prompt to its model CLI: `codex_adapter.py` writes it to the stdin of `codex exec` and reads the answer from the `--output-last-message` file; `generic_json_adapter.py` writes it to the stdin of `MODEL_CLI` and reads the answer from stdout; `prompt_arg_adapter.py` appends it as `-p PROMPT` to the command line, with a 32,000 UTF-16 unit cap, and runs the CLI in a fresh Git repository; `stdin_repo_adapter.py` writes it as UTF-8 bytes to the stdin of the CLI, with no cap and no prompt option, in the same fresh-repository isolation; `fresh_repo.py` is not a bridge but the shared isolation code that the last two import. The runner hashes all five into the judge signature, so editing any of them, or moving a judge from one to another, changes the signature and the calibration must rerun (calibration 4, task 1.9, for the agy judge's move to `stdin_repo_adapter.py`).

The runner sets `WQ_EVAL_FINAL_RESPONSE_FILE` to an absolute, unique per-call path for trusted adapters that obtain a provider's final message through a file. The Codex adapter passes this path to `--output-last-message`; the runner reads the file after the subprocess ends, including after a nonzero exit or process-tree timeout. When that file exists, its bytes become `response.bin` and determine `response_sha256`. The adapter's captured stdout remains in `adapter-stdout.bin` with `adapter_stdout_sha256`; provider progress and diagnostics remain in `stderr.bin`. Adapters that do not write the sidecar keep the normal stdout response contract. A failed call stays in `records.json` as an invalid record with a `failure_kind` (`plumbing` for a timeout, a launch error or a nonzero exit; `judgment` for an answer that failed validation; `skipped` for a pair that was too long to send). The runner never retries a call by itself; `rerun-failed --from RUN --out NEW_RUN` runs the `plumbing` failures of a finished comparison once more and marks each redone record `attempt: 2`.

A comparison of many documents can run in chunks. `compare --documents ID [ID ...]` runs only the named documents of the split. `merge --runs RUN RUN ... --out MERGED` (with the same `--suite`, `--rubric`, `--config` and `--calibration` as the chunks, and `--calibration-suite` when `compare` needed it) rebuilds one report from finished chunk runs made with the same suite, rubric, config, judge signature, candidate, baseline and tool versions, with no shared document and no writer failure; it never changes a chunk folder. Every comparison also writes `instructions.json`, the exact text the writer was given. `CONTRACT.md` (Plumbing and failure kinds) lists every refusal.

A suite with an `owner_session` case holds your own writing, so `calibrate`, `compare`, `merge`, `rerun-failed`, `optimize` and `prepare-optimize` refuse to write its run anywhere outside the existing folder that the environment variable `WQ_EVAL_PRIVATE_ROOT` names; set it before the run. To share a result, `export --report RUN/report.json --out FILE` writes only an allowlisted aggregate (counts, per-lane document and decisive counts, means, Wilson bounds and both directional sign-test p-values, the recommendation, check names and flags, hashes and tool versions), never a case, document or cluster id, a prompt, context, candidate text, quote, reason or path. `CONTRACT.md` (Private outputs and the export allowlist) lists the fields and the refusals.

Pin an available model explicitly in each adapter command (the Codex wrapper accepts `--model MODEL_ID`) and declare a version command for each CLI (next paragraph but one) so that the run records the versions it used. The calibration signature hashes declared judge IDs, families and command arguments, and the text of every shipped adapter script (`codex_adapter.py`, `fresh_repo.py`, `generic_json_adapter.py`, `prompt_arg_adapter.py` and `stdin_repo_adapter.py`; a test holds that list equal to the `*.py` files in `adapters/`); it cannot detect a provider changing its default model behind unchanged arguments. Recalibrate after changing model or adapter settings, after editing any of those scripts, or after moving a judge from one adapter to another, because each of these changes the judge signature and an older calibration then no longer matches. A certificate made before the scripts were hashed no longer matches and must be recalibrated. Each script is hashed with CRLF read as LF, so a checkout that converts line endings keeps the signature of an LF checkout; any other change to a script alters it. The suite, rubric and config hashes in a run's provenance read CRLF as LF too, while the candidate skill hash covers the raw `SKILL.md` bytes. A certificate issued before this normalization, on a checkout whose files had CRLF line endings, no longer matches and must be recalibrated. The generic bridge turns the JSON request into a role-specific prompt for a CLI that accepts a prompt on stdin and returns raw JSON on stdout; its command flags depend on the CLI you install.

Declare `version_commands` to have every run record its tool versions: an object that maps a name (letters, digits, `.`, `_` or `-`) to an argv array that prints that tool's version, for example `{"claude": ["claude", "--version"], "agy": ["agy", "--version"], "codex": ["codex", "--version"]}`. `calibrate` and `compare` run each command before the run (a failure stops the run before any output folder exists) and again after it, and record `provenance.tool_versions` as `before`, `after` and `changed` (the names whose version differs or could not be read the second time). A change adds a failed `tool_versions_stable` check and sets `eligible` to `false`; in `compare` it also turns every recommendation into `inconclusive`, and the judgments stay on disk. A version command reports its first non-blank stdout line (its first non-blank stderr line when stdout has none), runs with no stdin from a temporary scratch folder, is stopped after 30 seconds, and is not charged to `max_calls`. Its first element is looked up on `PATH` (a bare `codex` finds `codex.cmd` on Windows) and the other elements are used as written, so give an absolute path or a program on `PATH`; unlike adapter commands it is not resolved against the config folder. A CLI that updates itself in the middle of a run therefore voids that run. Without `version_commands` nothing is recorded.

Declare `isolation_probe` to have `compare` check, before any model call, that the writer CLI puts nothing of yours in front of the skill under test (a project instruction file, a memory file or a settings preamble would all count as prompt text). It is an object with exactly `command` (the writer CLI's argv with its JSON output on, tools off and no session saved) and `max_prompt_tokens` (a positive integer), for example `{"command": ["claude", "-p", "--model", "claude-sonnet-5-5", "--safe-mode", "--no-session-persistence", "--output-format", "json"], "max_prompt_tokens": 10000}`. The probe sends the fixed line `Reply with the single word ok.` on stdin from a scratch folder and adds up `input_tokens`, `cache_creation_input_tokens` and `cache_read_input_tokens` from the JSON reply; a sum above `max_prompt_tokens` means something else reached the model with that line, and the run refuses before the output folder exists. It refuses the same way when the probe cannot start, runs past the config's `timeout_seconds`, exits nonzero, reports an error or prints JSON that cannot be parsed. `CONTRACT.md` quotes the three messages, and the contract tests pin them. Set the limit from a measured baseline for your writer settings plus headroom, since the sum includes the CLI's own system prompt. The probe costs one small model call per `compare`; `calibrate`, `optimize` and `rerun-failed` never call the writer, so none runs it. A passing probe records `provenance.isolation_probe` (the command's hash, the limit and the measured sum). A config without `isolation_probe` behaves as before.

Pin the reasoning effort too, so a provider default cannot change between two runs. The Codex wrapper takes `--reasoning-effort LEVEL` and sends it as `-c model_reasoning_effort=LEVEL`; LEVEL is one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh` or `max`, and any other value exits 2 before Codex starts. Without the option the wrapper passes no effort setting and Codex keeps its own default. Codex 0.156.0 ships no configuration docs, so that list was measured: Codex echoes any value in its banner, and the API refused an unknown one (checked with `gpt-6-astra`; a given model may accept fewer values). An agy model slug carries its own level (for example `gemini-3.1-pro-high`). Put a judge's effort flag in that judge's command: the calibration signature covers it, so changing it means recalibrating. The writer and optimizer commands are outside that signature.

Claude Code 2.1.281 takes `--effort LEVEL` (`low`, `medium`, `high`, `xhigh` or `max`; an unknown value only prints a warning and the call runs at the default effort), but an inherited `CLAUDE_CODE_EFFORT_LEVEL` beats the flag. This was measured by reading the request body that a call sent to a local stand-in server (no model call): with the variable set to `max`, `--effort high` still sent `output_config.effort` as `max`, while adding `--settings '{"env":{"CLAUDE_CODE_EFFORT_LEVEL":"high"}}'` sent `high`. A writer command that must hold its effort therefore carries both, or the shell that starts the run unsets the variable. Nothing in Claude's stream output or debug log named the effort in force in that test, so recheck it the same way after upgrading.

The Codex adapter also keeps your own Codex setup out of every call. It skips `config.toml` and execpolicy rules, disables plugins and ChatGPT apps, stops project documents and the skills listing from loading, and passes `--strict-config` so a renamed setting fails the call instead of silently dropping the isolation; these options were measured on Codex CLI 0.156.0, so recheck them after upgrading. Residual exposure: Codex 0.156.0 documents no option that skips the global `~/.codex/AGENTS.md`, so its text still reaches every Codex call.

`adapters/prompt_arg_adapter.py` serves a CLI that takes its prompt as the value of `-p`; agy 1.2.12 was recorded as not reading stdin, and the 1.2.14 measurement dated below found that it does when `-p` is absent, so the `-p` transport is a choice that keeps the calibrated call unchanged. Put `py -3.11 prompt_arg_adapter.py -- MODEL_CLI ARG...` in the command array (with the CLI's `--model` pinned in ARG); the wrapper builds the same prompt as the generic bridge and appends `-p PROMPT` as the last argument. It runs the CLI in a new temporary directory that it makes a Git repository with `git init`, then removes the directory. The repository matters: agy loads an `AGENTS.md` found by walking up from its working directory to a Git root, and the temp folder can sit under one, so an ordinary temp directory can pull in a parent project's instructions. An empty `.git` folder did not stop that walk in testing; a real repository did. Neither git nor the CLI inherits a `GIT_*` variable, because `GIT_DIR` or `GIT_WORK_TREE` would point both at some other repository. Before the CLI starts, the wrapper exits 2 if git is missing, `git init` runs past 30 seconds, git leaves no `.git/HEAD`, the target is a `.cmd` or `.bat` file or is `cmd`, `powershell` or `pwsh` (a shell would re-parse the prompt), an argument starts with `--dangerously`, the prompt is not valid UTF-8, or the command line would pass 32,000 UTF-16 units (the shipped judge prompts need at most about 1,800). A CLI exit code passes through, except that on POSIX a CLI killed by a signal exits 128 plus the signal number (137 for SIGKILL), as a shell reports it; exit 0 with blank stdout becomes exit 2, because agy exits 0 with no output when it is denied a tool call. A call that the runner kills on a timeout can leave a small `wq-prompt-arg-*` folder in the temp directory. Residual exposure: agy 1.2.12 offers no option that skips the global `~/.gemini/GEMINI.md` or its built-in skills listing, so both still reach every agy call. Measured 2026-09-30 with agy 1.2.14 and `--model gemini-3.8-flash-high` (`tools/measure_agy.py`, below): a call with `-p` absent and the prompt on stdin answered it (exit 0) while `-p ""` exited 1 with `empty prompt`, so this agy reads stdin; a canary `AGENTS.md` in a scratch parent folder reached a plain child folder but not a fresh `git init` repository beside it, so a real repository still stops the walk. The prompt, which holds the text under review, is also a command-line argument of the CLI, so any local process that can read other processes' command lines sees it while the CLI runs; `stdin_repo_adapter.py` (next paragraph) does not have this exposure. These behaviors were measured on agy 1.2.12 (the `AGENTS.md` walk again on 1.2.14), so recheck them after upgrading.

`adapters/stdin_repo_adapter.py` serves agy with `-p` left out: it writes the prompt to the CLI's stdin as UTF-8 bytes and closes stdin, so the command line carries no prompt. There is no 32,000 unit cap, and the text under review stays out of the process list. Put `py -3.11 stdin_repo_adapter.py -- MODEL_CLI ARG...` in the command array (with the CLI's `--model` pinned in ARG); ARG must not be `-p`, `--prompt` or `--prompt=...`, and the wrapper exits 2 on one, because agy ignores stdin when it is given a prompt option. The prompt is the generic bridge's, byte for byte. The runner's pre-judge size check measures only commands that use `prompt_arg_adapter.py`, so a judge on this adapter is never skipped as oversized, and a test runs a 100,000-character case through it. The wrapper keeps every protection of `prompt_arg_adapter.py`: the fresh Git repository, no `GIT_*` variable, the refusals before the CLI starts (git missing or hung, no `.git/HEAD`, a `.cmd` or `.bat` file or a shell, `--dangerously*`, a non-UTF-8 prompt), exit 2 for exit 0 with blank stdout, signal exits as 128 plus the signal number, and stdout passed on as it arrives so a timeout keeps partial output. The shared code is `adapters/fresh_repo.py`. A second thread writes the prompt while the main thread streams stdout, so a prompt larger than a pipe buffer cannot deadlock a CLI that echoes while it reads (a test sends more than 1 MB through a stand-in that does). If the CLI exits 0 without taking the whole prompt, the wrapper exits 2, because that answer rests on text the model never saw; a CLI's own nonzero exit code passes through. A call that the runner kills on a timeout can leave a small `wq-stdin-repo-*` folder in the temp directory. Measured 2026-10-01 with agy 1.2.14, `--model gemini-3.8-flash-high`, `--sandbox --output-format text`, in a fresh `git init` repository: a 41-line prompt and a prompt of about 96,000 characters on stdin were each read whole, and curly quotes, accented letters and Japanese text came back exactly. Moving the agy judge from `prompt_arg_adapter.py` to this adapter changes its command and the hashed adapter text, so the judge signature changes and the calibration must rerun (calibration 4, task 1.9).

`tools/measure_agy.py` measures an installed agy; a person runs it, it makes a few Gemini calls, and CI never runs it. From the repository root, run `py -3.11 -m evaluation.benchmark_v2.automated.tools.measure_agy AGY_PATH --model MODEL --out RESULT.json`. It records the `--version` text; whether agy reads a prompt from stdin (the same call with `-p` absent and with `-p ""`, each given a prompt on stdin that asks for a random token to repeat); and whether agy loads a parent folder's `AGENTS.md` (a canary word sits in a scratch parent folder, and agy is asked for it once from a plain child folder and once from a fresh `git init` repository beside it). Every call passes `--sandbox` and the pinned model, never `--dangerously-skip-permissions`, and none inherits a `GIT_*` variable. The script never overwrites a result file and writes `inconclusive` for a question whose calls failed or timed out; the JSON keeps each call's exit code, stdout and stderr.

The judge returns `{"winner":"A|B|tie|both_bad","reason":"...","evidence":[{"candidate":"A|B","quote":"literal excerpt"}]}`. Decisive and both-bad judgments must quote both candidates; a tie must quote at least one candidate (an empty evidence list is invalid for every winner). The writer receives the skill's treatment snapshot as `instructions` and returns `{"text":"nonblank response"}`. The snapshot is the `SKILL.md` text followed by every file under the `references/` folder beside it, each behind a `=== references/<path> ===` header, read as UTF-8 with CRLF read as LF and capped at 60,000 characters (a larger one is refused before any output exists; `CONTRACT.md`, "Treatment snapshot", has the exact format). `--candidate-skill` and `--baseline-skill` each take a skill folder or its `SKILL.md`, and both follow the same rule. With no `--baseline-skill` the baseline writer's instructions read `No additional instructions.` The run records `candidate_snapshot_sha256` and `baseline_snapshot_sha256`; `candidate_skill_sha256` still hashes the raw `SKILL.md` bytes. A comparison evaluates the snapshot, not the entire routed portfolio: a file the skill points to outside its `references/` folder is not included.

After configuring adapters, run calibration before comparison. These are command templates; no live run is claimed here:

```sh
python -m evaluation.benchmark_v2.automated calibrate --suite evaluation/benchmark_v2/automated/data/controls.json --rubric evaluation/benchmark_v2/automated/data/rubric.json --config evaluation/benchmark_v2/automated/adapters/local-config.json --out .eval-runs/calibration-1
python -m evaluation.benchmark_v2.automated compare --suite evaluation/benchmark_v2/automated/data/controls.json --rubric evaluation/benchmark_v2/automated/data/rubric.json --config evaluation/benchmark_v2/automated/adapters/local-config.json --calibration .eval-runs/calibration-1 --candidate-skill skills/concision --repetitions 1 --out .eval-runs/comparison-1
python -m evaluation.benchmark_v2.automated prepare-optimize --suite evaluation/benchmark_v2/automated/data/controls.json --out .eval-runs/optimize-suite-1.json
python -m evaluation.benchmark_v2.automated optimize --suite .eval-runs/optimize-suite-1.json --rubric evaluation/benchmark_v2/automated/data/rubric.json --config evaluation/benchmark_v2/automated/adapters/local-config.json --rounds 2 --out .eval-runs/optimization-1
```

Calibration requires at least eight labeled controls across four documents, two presentation orders per judge, complete valid coverage, and engineering-default thresholds of 0.90 for stable correctness and order stability. A comparison requires a matching eligible **live** calibration for the same rubric and judge signature. It scores the `test` split unless `--split` names another. It samples independent documents and treats ties, abstentions and disagreements as zero preference. Per lane it reports the share of decisive documents that favor the candidate with a two-sided 90% Wilson score interval and two one-sided sign-test p-values (exact binomial tests, one per direction), and it recommends a candidate only if every evaluated lane has a Wilson lower bound above one half, a mean net preference of at least 0.15, a candidate sign-test p-value of at most 0.05 and passing deterministic checks (`CONTRACT.md`, Statistics, has the formulas). A lane favors the baseline by the mirror rule: a Wilson upper bound below one half, a mean of at most -0.15 and a baseline sign-test p-value of at most 0.05. The p-value condition keeps a very small sample from deciding; for example, three or four decisive wins and no losses stay inconclusive, because the smallest p-value at four decisive documents is 0.0625. Otherwise it can recommend retaining the baseline or report inconclusive. A literal check miss on a `synthetic_control` or `published_reference` case vetoes a recommendation for the side whose text missed; on an `owner_session` case it is only a diagnostic (`counts.candidate_check_diagnostics`, `counts.baseline_check_diagnostics` and the `diagnostics` list) and the lanes' judge results decide, as `CONTRACT.md` states. The controls are public synthetic checks, so even a passing proxy does not establish an expert or held-out quality result. `prepare-optimize` writes a new, validated calibration/development-only subset from a mixed starter suite without human filtering or labels; it refuses to overwrite a file. Optimize uses only that subset and stops after at most three proposed rounds; it never edits a skill or admits test examples.

## Plugin Eval extension or direct JSON

The optional local-only metric pack reads an **existing** report; `analyze` never starts model work. Install Plugin Eval's CLI so `plugin-eval` is on `PATH` (the installed package declares that binary at `scripts/plugin-eval.js`). If your installation does not expose a command, replace `plugin-eval` below with `node PATH_TO_PLUGIN_EVAL/scripts/plugin-eval.js`, using your own installed package path. The manifest calls `python`; if your Python 3.11+ executable has another name, update only that command's executable. Choose the exact report file emitted in the comparison output directory and analyze the same skill snapshot. `WQ_EVAL_REPORT` must be absolute because Plugin Eval starts the adapter from the manifest directory. From the repository root, on POSIX:

```sh
WQ_EVAL_REPORT="$(pwd)/.eval-runs/comparison-1/report.json" plugin-eval analyze skills/concision --format json --metric-pack evaluation/benchmark_v2/automated/plugin_eval/manifest.json
WQ_EVAL_REPORT="$(pwd)/.eval-runs/comparison-1/report.json" python evaluation/benchmark_v2/automated/metric_pack.py skills/concision skill
```

In PowerShell:

```powershell
$env:WQ_EVAL_REPORT = (Resolve-Path '.eval-runs/comparison-1/report.json').Path
plugin-eval analyze skills/concision --format json --metric-pack evaluation/benchmark_v2/automated/plugin_eval/manifest.json
python evaluation/benchmark_v2/automated/metric_pack.py skills/concision skill
```

The direct Python command prints only the extension JSON and does not require Plugin Eval. The manifest supports `skill` and `plugin`; plugin roots with more than one skill are ambiguous and yield a warning, so analyze a specific skill in this portfolio. The extension verifies the report schema, suite/rubric/config/judge provenance digests, and the candidate skill hash against raw `SKILL.md` bytes. It trusts the selected local report as runner evidence; hashes detect mismatch, not malicious fabrication. Missing, stale, mismatched, calibration or demo evidence yields warnings, no quality pass. Valid numeric metrics, including per-lane document and decisive counts, Wilson bounds and the two directional sign-test p-values (for the editing lane, `wq-automated-editing-sign-test-p-candidate` and `wq-automated-editing-sign-test-p-baseline`), appear under `extensions[]` with `wq-automated-*` IDs; a numeric entry in the report's own `metrics` object is passed through the same way, so one named `wilson_lower` appears as `wq-automated-wilson-lower`. They never replace Plugin Eval's core score. The quality pass also rechecks each lane's Wilson lower bound, mean net preference and candidate sign-test p-value (at most 0.05), so a report without `sign_test_p_candidate` earns no pass. Baseline check failures remain visible warnings even when an eligible live report recommends the candidate; candidate/coverage/calibration failures prevent the extension's quality pass.

## Public reference examples

`data/references.json` contains three small audience-guidance comparisons. Candidate A is excerpted from [GSA's archived plain-language guidance](https://github.com/GSA/plainlanguage.gov/blob/main/_pages/guidelines/audience/index.md); candidate B is a new adaptation, with distinct SHA256 hashes for both UTF-8 strings in each provenance note. The [repository license](https://github.com/GSA/plainlanguage.gov/blob/main/LICENSE.md) declares U.S. public domain and CC0 1.0 worldwide. All cases have `split=development`, `expected=null`, and `kind=published_reference`; authorship gives no winner label. The three examples cover only short government guidance sentences in the editing lane, so they cannot validate memos, literary prose, long-form cohesion, communication replies or other genres.

To add material without human grading, secure the original publisher's reuse license first. Save source URL, license identifier/URL, an exact short excerpt and its UTF-8 SHA256; write an alternate candidate with its own hash and note which text is adapted. Add a unique case/document ID, `split=development`, `expected=null`, lane/prompt/context and `checks={}`. Run the `validate --suite ... --rubric ...` command above with your expanded suite. Do not infer preference from published authorship and do not move an inspected public example into a sealed test set.
