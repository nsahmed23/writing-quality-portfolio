# Portfolio root-cause analysis

## Bottom line

The pilot did not test a native executable portfolio detector. It asked one model to project seven revision-oriented skill contracts into a shared detect-only schema, map them into a public taxonomy, calculate exact offsets, arbitrate collisions, and serialize all 72 cases in one response.

The portfolio's low exact scores therefore combine adapter, routing, span, taxonomy, and diagnostic behavior. Its apparent case-level strength is contaminated by label-revealing IDs. The evidence supports improving the executable architecture before adding a broad collection of new triggers.

## Observed behavior

The three portfolio runs localized a CHANGE somewhere in 31, 33, and 34 of the 36 provisional CHANGE cases. They made one clean-case error across the three runs. These are descriptive counts only because the public identifiers disclosed which cases were positive.

Exact finding precision and recall were much lower. The gap between case localization and exact credit came largely from boundary and label choices. For example, a predicted span that included terminal punctuation received no exact credit, and `unjustified_certainty` received no credit when gold used `claim_evidence_mismatch` for the same assertion.

## Causal factors

### Natural-language routing was not enforced

The portfolio documents minimal activation, skipped empty passes, one owner per fault, clean-span preservation, and collision ownership. The evaluator supplied all seven skills at once. It recorded no deterministic route, selected owner, arbitration decision, or rejected duplicate.

The same underlying issue therefore received different owner and taxonomy names across runs. Routing existed as prose but was not an auditable execution layer.

### Detect-only and revision contracts conflict

The common envelope prohibited rewriting. Portfolio pass order and several skill contracts describe changed spans, downstream revision passes, and integrated revised text. In detect-only mode, a model could stop later passes because no revision exists or ignore the pass contract and fan out. Either interpretation changes the measured system.

### The portfolio has preservation rules but no exact KEEP emission protocol

The seven skills contain safeguards for legitimate passive voice, nominalizations, technical terms, repetition, fragments, uncertainty, and author voice. Those contracts commonly say to stop, skip, or leave text unchanged. The benchmark instead asked for exact explicit KEEP findings with offsets and codes.

Conservative non-editing and exact protected-region reporting are different capabilities. Public empty protection lists made the mismatch worse.

### Several skills require missing context

Doc typing asks about reader activity, knowledge state, and promised outcome. Memo structure asks about audience, decision, deadline, and constraints. Usage adjudication asks about register, dialect, field, audience, and current evidence. The job schema allowed no clarification or `needs_context` response and disabled network access.

### Exact span policy was underspecified

The shared wrapper required correct offsets but did not define the minimum defect-bearing unit, punctuation treatment, split-versus-bundle policy, or precedence between related clauses. A deterministic adapter should own offsets rather than asking every specialist projection to solve them.

### Shared taxonomy both broadened and penalized the portfolio

The public taxonomy exposed mechanisms such as `causal_overclaim`, `chatbot_artifact`, `privacy_exposure`, and `unsupported_specificity`, whether or not the seven skills natively owned them. It then penalized plausible alternate family choices through exact one-label scoring.

## Likely real gaps, pending human adjudication

The most consistent portfolio omission was leaked editing or prompt instruction text. Narrow mechanism candidates also include:

- claim and evidence integrity;
- public-data sanitation and privacy;
- structured source and diff integrity;
- attribution, comparison, date, actor, modality, and negation checks;
- second-language voice calibration.

These should not be imported wholesale. Each needs development-set evidence of incremental value without unacceptable false positives or meaning changes.

## Why earlier portfolio tests did not expose this

The published portfolio validator checks fixture counts, categories, IDs, and expected-behavior fields. It does not invoke the skills and compare model outputs to adjudicated findings. The validation report correctly calls the suite schema and expectation checks rather than a blinded model evaluation.

The portfolio had a strong specification test suite, not an executable diagnostic performance test. Conflating those was part of the original oversight.

## Reoptimization order

1. Separate native specialist diagnosis from taxonomy normalization.
2. operationalize routing, ownership, and arbitration as recorded intermediate decisions.
3. Define deterministic quote-anchor and minimal-span rules.
4. Add taxonomy aliases, precedence, or hierarchical credit.
5. Preserve exact rendered prompts and run independent case requests.
6. Convert existing fixtures into executable CHANGE and KEEP tests.
7. Add only narrow missing mechanisms that survive human-adjudicated ablation.
