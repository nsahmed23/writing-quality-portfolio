## Scope and claims

Add `evaluation/benchmark_v2/automated/`, using Python >=3.11 and the standard library. It is a new **automated_proxy** protocol, not fulfillment of the archived human-review protocol. Human review is not a prerequisite or an escalation queue. Missing evidence, failed calibration and disagreement produce inconclusive outcomes automatically. Demo adapters produce software smoke evidence only; they cannot certify quality or recommend a candidate.

The Unslopping blog inspires compact, task-aware rubrics, calibration and separation of evaluator optimization from writer optimization. This repository does not train model weights or claim to reproduce RL-XAR. Published reference authorship is provenance, not a guaranteed winning label. Starter controls and development examples are public, not a sealed or contamination-free test set. This milestone supports bounded refinement of rubric descriptions through a configured optimizer, not automatic editing or deployment of skills.

## Data contracts

Suite JSON: `schema_version: 1`, nonblank `name`, and nonempty `cases` array. A case has unique nonblank `id`, nonblank `document_id`, `split` in calibration/development/test, `lane` in editing/communication, nonblank `prompt`, string `context`, nonblank strings `a` and `b`, `expected` in a/b/tie/both_bad/null, `checks` object, and `provenance` object containing `kind`, `source`, `license`. Kinds are synthetic_control or published_reference. All members of a document must use one split. Reusing the same normalized context/prompt/pair under different document IDs must be rejected in any split; repetitions under the same document ID remain valid. Published references must have expected=null; do not turn human authorship into gold. `checks` supports only optional `required` and `forbidden` string arrays, positive integer `max_words`, and string `exact`. These checks apply to each candidate independently; membership is literal and is not semantic truth verification. Unknown fields, invalid Unicode, duplicate JSON keys and nonfinite values are rejected. Optional provenance `note` is allowed.

Rubric JSON: `schema_version: 1`, nonblank `id`, `criteria` array of 1..8 unique objects with nonblank `id` and `description`; total descriptions <=6000 characters. Initial criteria cover task/purpose, meaning, useful specificity, economy, cohesion and voice. No vocabulary blacklist or required formatting style.

Model judgment raw JSON: exactly `winner` in A/B/tie/both_bad, nonblank `reason`, nonempty `evidence` array of objects `{candidate: A|B, quote: nonempty string, occurrence?: positive integer}`. Every quote must resolve literally and unambiguously through existing resolve_anchor. This validates attribution, not whether evidence supports a conclusion. Both candidates must have quoted evidence for a decisive or both_bad judgment; a tie may cite one. Reject malformed output without silently extracting JSON from prose. Records use canonical lowercase a/b after reversing displayed order when necessary.

Common record: `case_id`, `document_id`, `lane`, `split`, `judge_id`, `family`, `order` (1|2), `valid` boolean, `winner` (canonical a|b|tie|both_bad|null), plus optional `error`. Exactly one record per case/judge/order; duplicates invalidate coverage. Multiple writer repetitions have distinct case IDs, retain the same document ID and receive equal weight within that document.

Report contract: `schema_version:1`, `evaluation_type:automated_proxy`, `execution:live|demo`, `mode:calibrate|compare|score`, booleans `complete` and `eligible`, `recommendation:candidate|baseline|inconclusive|not_applicable`, `metrics` numeric object, `checks` array of `{id,passed,message}`, `by_judge` and `by_lane` objects, `counts` object. Runner adds suite/rubric/config/skill digests and artifact provenance. Missing or invalid results are never counted as passes. Reports contain no human-validation claim.

## Engine interfaces and decision rules

`contracts.py`: `load_suite(path)->dict`, `validate_suite(value)->dict`, `load_rubric(path)->dict`, `validate_rubric(value)->dict`, `strict_json(raw:bytes)->object`.

`scoring.py`: `check_text(text:str, checks:dict)->list[dict]` (each id/passed/message); `parse_judgment(raw:bytes,a:str,b:str)->dict` (valid/winner/error; winner A/B/tie/both_bad until runner maps it); `build_report(suite:dict, records:list[dict], judges:list[dict], *, mode:str, calibration:dict|None=None, execution:str='live', seed:int=0)->dict`.

Each configured judge has nonblank id/family. A complete live comparison requires >=2 distinct judge families. Evaluate both presentation orders; a judge contributes a case result only if both valid outputs agree after canonical mapping. All judges must agree for a decisive case result. Other cases are inconclusive and contribute zero to the all-case preference estimate; keep their counts visible. Report abstentions separately from ties and both_bad.

Calibration uses expected-labeled calibration cases only: at least 8 controls and 4 documents per judge, >=0.90 correct stable results, >=0.90 order stability, complete valid coverage. These are explicitly configurable-in-code initial engineering defaults, not scientifically established thresholds. All configured judges must qualify; do not silently drop failed judges. Comparison requires a matching eligible live calibration certificate; the runner enforces identical rubric and judge signatures. Demo certificates are never eligible.

Comparison deterministic failures on candidate b block recommending it. Report candidate/baseline check failures separately. Within each lane, map unanimous stable a=-1, b=+1, tie/both_bad/inconclusive=0. Average repetitions/cases per document, then average documents. Seeded 2000-sample bootstrap resamples documents, not judgments. Require >=5 independent documents per lane and a lower 95% percentile bound >0 to recommend candidate; upper bound <0 recommends baseline; otherwise inconclusive. Overall recommendation candidate requires every evaluated lane candidate, and baseline may be retained for any failed gate; never manufacture a total score across lanes. Null denominators are omitted, not invented zero values. Calibration mode recommendation is not_applicable.

## Runner, adapters and isolation

`python -m evaluation.benchmark_v2.automated` exposes `demo --out DIR`, `calibrate --suite PATH --rubric PATH --config PATH --out DIR`, `compare --suite PATH --rubric PATH --config PATH --calibration DIR --candidate-skill PATH [--baseline-skill PATH] [--repetitions N] --out DIR`, `optimize --suite PATH --rubric PATH --config PATH [--rounds N] --out DIR`, and `validate --suite PATH --rubric PATH`.

Config: `schema_version:1`, `judges:[{id,family,command:[argv...]}]`, optional `writer:{id,family,command:[...]}`, optional `optimizer:{id,family,command:[...]}`, `timeout_seconds` (default120, >0 <=600), `max_calls` (default200, positive integer). Resolve config-relative executable/script paths predictably; use argv and shell=False. Document commands as trusted local adapters. No secrets embedded in examples. Provide a small generic stdin/stdout model-CLI bridge alongside the Codex adapter, so a second provider does not require users to write Python. One JSON request on stdin, one raw UTF-8 JSON response on stdout; stderr is retained separately. Calls use fresh subprocesses and minimal temporary working directories with only their request. Never place suite files, private expected labels, held-out examples or candidate identity in a judge request. This is process/workspace separation, not an OS sandbox or a guarantee about provider retention.

Judge request: `{role:'judge', request_id:opaque_hash, prompt, context, rubric:criteria, A, B}`. Writer request: `{role:'writer',request_id,prompt,context,instructions}`; response exactly `{text:nonblank string}`. Instructions are the requested SKILL.md contents (or empty for baseline). A skill directory resolves to SKILL.md. If a skill relies on external references, document that this adapter evaluates the supplied instruction snapshot; do not claim full routed-portfolio execution. Optimizer request includes current rubric, allowed calibration/development examples and feedback only; response is rubric JSON. It never receives test examples. Bound rounds to 1..3 and preflight request count against max_calls before model work. Refuse suite splits with test in optimize. Compare only selects test cases and calibration only selects calibration cases; selected public starter test examples remain explicitly public development evidence.

Raw request bytes, first response bytes, stderr, return code, elapsed time and SHA256 hashes are preserved per call before parsing. New output directory must not exist; never overwrite evidence. Provider errors/timeouts/nonzero exit produce invalid records and visible incomplete reports. Save all raw output even when parsing fails; a timeout's partial bytes must survive. The runner provides an optional absolute `WQ_EVAL_FINAL_RESPONSE_FILE` path to adapters that use final-message files; after exit or timeout it recovers those bytes and preserves adapter stdout separately. No automatic retry that could hide failures. Preserve generated texts and skill snapshots. Supplied adapters may record token telemetry in stderr; do not fabricate token counts. Static demo makes no external calls and clearly identifies synthetic judgments.

Optimize evaluates the starting rubric and up to 3 proposed rubrics on labeled calibration controls, with development controls used for selection where available; no test use, no claim that control accuracy measures expert writing. Save every candidate and feedback; freeze the selected rubric and require fresh live calibration before compare. If no improvement, retain the starting rubric. Stop on budget exhaustion with explicit state. No self-modifying skill loop in this milestone.

## Starter evidence and Plugin Eval

Ship >=12 controlled pairs spanning deadline/fact preservation, qualification preservation, explicit scope, exact output, irrelevant padding and unchanged effective prose. Group paired variants by source document. Include both lanes and at least 4 calibration documents; additional development/test controls are labeled synthetic. Demo must show both a successful software path and at least one rejected/inconsistent model-judgment path, but cannot produce quality approval.

Ship a small documented reference suite from permissively reusable primary-source prose, with source URL/license and exact text hashes; all have expected=null, are development examples, and are not claimed to cover all writing genres. Include an import/validation recipe for expanding it without human grading. If primary-source licensing cannot be established, use source links and an example import schema without copying text; never invent license status.

Metric pack under `evaluation/benchmark_v2/automated/plugin_eval/`: manifest names the local Python adapter, supports skill/plugin, emits only checks/metrics/artifacts. It loads an explicitly selected report via `WQ_EVAL_REPORT`, verifies schema plus required provenance and skill snapshot hash against the supplied target, maps independent metrics to stable IDs, and refuses a missing/stale/mismatched report. Demo evidence is warning-only. It cannot overwrite Plugin Eval's core score. A JSON report CLI is available without Plugin Eval. Tests run with a temporary report and real adapter invocation; controller also runs installed plugin-eval analyze with this manifest.
