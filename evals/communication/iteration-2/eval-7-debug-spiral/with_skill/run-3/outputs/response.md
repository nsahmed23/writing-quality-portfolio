Before another selector or wait change: see what CI actually renders when it times out. Pull the trace or screenshot Playwright already captured for the failed run if CI saves one, or add a single `page.screenshot()` (or `page.content()`) call right before the assertion and rerun. That replaces guessing with a direct look at the page.

The three fixes so far all assumed the heading is slow to arrive, and the results argue against that. Raising the timeout to 15s argues against "just needs more time." `waitForLoadState('networkidle')` argues against "pending network calls still in flight." Swapping to `getByTestId('metrics-heading')` and hitting the exact same timeout is the strongest signal: a testid query failing identically to a role query usually means the heading is not present or not visible, not that the query itself was wrong. The failure is also 100% consistent on CI and 100% consistent locally, which argues against a race condition too: races are typically flaky in at least one direction, not perfectly deterministic in both.

That points upstream of the locator: something differs between CI and local before the Metrics component ever renders. Candidates: a data fetch the component depends on fails or hangs in CI (missing API key or backend URL in CI env or secrets), an auth or session check redirects before the dashboard loads, or CI points at a different base URL than the local dev server. These are hypotheses, not a diagnosis.
